# 逐财年普通股息对账 v2

本轮只处理 `dividend-candidates-v1` 覆盖的 56 家公司，并查看
`official_backfill_v1` 中每家公司最近最多 5 个完整财年。实际形成 277 个“公司 × 财年”位置：

- 16 个位置已核清，可以交给受控导入器读取；其中 14 个是本轮新增，2 个沿用并重新校验 v1 证据。
- 261 个位置暂不填数字，也不填 0。每个位置均在 `blocked/` 中写明目前缺少哪一步。

“已核清”在这里仅表示：普通现金股息的完整财年总额、实际支付状态、币种以及官方来源可以相互对上。它不表示整家公司已经满足 v2 的全部数据要求，也不等于公司发布状态 `VALID`。

## 接受标准

一个财年只有同时满足以下条件才进入 `distributions/`：

1. 官方完整年报明确指向目标财年；
2. 明确是普通现金股息，不含特别股息；
3. 年报明确记载已实施或已支付；
4. 年报给出最终现金总额，或所有组成项都已找全并逐项核验；
5. 官方 PDF 路径、SHA-256、页码和原文标记均与年报来源账本一致；
6. 富途公司行动事件只能辅助确认实施日期和每股方案，不能代替官方年报；
7. 所有加总均使用 `Decimal`。

如果未来只能通过“每股金额 × 有权股份数”推导，总额计算器要求两个独立来源标识同时存在，并用 Decimal 验证等式。当前 16 个结果没有使用这种推导。

## 本轮需要特别说明的两项修正

汇川技术两个候选数字是方案披露时的预案总额。后续同一官方年报页还披露了最终实施总额，因此 v2 拒绝预案数字，改记实际派发额：

- FY2023：预案 `1,204,384,000.50` 元，实际 `1,204,746,677.55` 元；
- FY2024：预案 `1,104,385,494.78` 元，实际 `1,104,397,656.61` 元。

苏泊尔 FY2022 包含两个已实施的普通现金分红组成项：

```text
2,439,504,228.21 + 1,006,661,758.75 = 3,446,165,986.96 元
```

两个组成项分别绑定官方年报页和独立实施事件，不把同一分配的每股表示再次相加。

## 未核清位置是什么意思

`blocked/` 中的中文原因只表达当前证据缺口：

- “没有找到完整总额”：现有候选里没有一个数字能证明是该财年的全年普通股息；
- “组成项尚未核清”：可能找到了若干数字，但还不能证明中期、末期等已经全部找齐且没有重复；
- “港股币种或支付状态尚未核清”：年报披露需要继续核对币种、全年组成和最终支付状态；
- “普通/特别尚未拆开”：披露中两类分红并存，不能先把表面总额当作普通股息。

这些位置不是“候选为 0”，而是“现阶段不能安全给数字”。

## 构建、验证和读取

从 WebApp 根目录运行：

```bash
python scripts/support/reconcile_dividend_history.py
pytest -q tests/test_dividend_reconciliation_v2.py tests/test_import_dividends_v2.py
```

默认输出：

```text
../data/shareholder-v2/reconciliation/dividend-v2/
├── distributions/   # 16 个可读取的完整财年事实
├── blocked/         # 56 个公司文件，共 261 个未核清位置
├── report.json
└── manifest.json
```

只读入口：

```python
from liberty_v2.import_dividends_v2 import load_controlled_dividend_facts_v2

facts = load_controlled_dividend_facts_v2(
    "../data/shareholder-v2/reconciliation/dividend-v2",
    official_annual_root="../data/raw/annual_reports/official_backfill_v1",
)
```

`official_annual_root` 是必填项。导入器会重新读取每个来源 PDF，限制相对路径不得越出该根目录，并重新计算 SHA-256；因此即使对账完成后年报文件被替换，导入也会停止。

构建脚本拒绝非空输出目录，也拒绝把结果写入生产 staging、候选源目录、年报源目录或 v1 对账目录。本轮没有执行生产导入。
